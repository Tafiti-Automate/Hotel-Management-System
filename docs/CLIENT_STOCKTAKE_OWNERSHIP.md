# Client stocktake ownership correction
- Cost Controller owns Manage Inventory, Physical Stocktake, Usage, Stock Analysis and the report center; Financial Manager retains independent count approval and shared report access. Store Keeper keeps stock on hand, issues, transfers, GRNs, returns and return reconciliation evidence.
- Explicit server-side stocktake permissions reject Storekeeper read/write, including stale generic Django permissions. Count creation/entry/booking is scoped to the controller's active property; Finance cannot count or self-approve. Role template no longer grants keeper count CRUD.
- Both regular count screens and month-end allow adding a catalogue article found physically but absent from the store count. Four decimal nonnegative actual quantities may exceed theoretical quantities. Missing balances are represented as zero theoretical evidence without creating live stock. Unknown acquisition costs suppress variance value and block posting pending reconciliation; batch evidence must be reconciled before booking. Existing booked records are not rewritten.
- Purchase Analysis remains shared between Cost Control and Finance; Storekeeper no longer has the analytics report center. Stock Analysis shortcuts now open the actual shared reports.
- CI and client acceptance remain required. New unrecorded stock valuation must be verified via controlled reconciliation before booking; this change does not invent a cost or batch receipt.
